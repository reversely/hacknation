# Wren demonstration Space

A Hugging Face Space shows Wren on a desktop screen: a phone-sized Wren panel runs the onboarding
flow from the hi-fi design, and a narration panel beside it shows each step the system takes as it
happens. The Space runs in parallel with the phone app and changes nothing in it. It reuses the
app's TypeScript and runs every model inside the Space, with no Google, WhatsApp or ElevenLabs call
at run time. Tickets #43 to #47 build it.

## Conventions

- **Bundle:** the browser application in `space/web/`, written in TypeScript and built with bun.
- **Model server:** the Python Gradio application in `space/app.py` and `space/models/`, which loads
  the models and answers model calls.
- **Model call:** one request from the bundle to the model server.
- **Trace:** the list of steps a user action ran (stage, model, input, output, milliseconds, cache
  hit), which the narration panel renders.
- **Pinned revision:** a model repository commit SHA; no file loads from a branch name.

## Hosting

The Space uses the Gradio SDK on ZeroGPU hardware (decided by the user on 4 October 2026). Gradio
serves the bundle as static files and hosts the model calls as API functions decorated with
`@spaces.GPU`. ZeroGPU lends a GPU only for the length of each decorated call and charges that time
to the visitor's daily quota: 2 minutes without an account, 5 with a free account, 40 with PRO
(Hugging Face's ZeroGPU documentation). Each call carries a duration limit from `models.json`; the
default limit is 60 seconds. The Space runs every model in PyTorch through `transformers`, since
ZeroGPU supports only PyTorch.

## Phone panel

The phone panel follows the hi-fi onboarding design. Each screen collects one part of the farm
profile through ordinary form controls, so most of the flow runs without a model.

| Screen | Collects | Model use |
| --- | --- | --- |
| Choose your language | Interface language | None; interface text in each language ships with the Space |
| Sign in to Wren | A mock "Continue with Google" step | None; the Space makes no Google call |
| Tell us about your business | Phone number, optional photos | None |
| Services | For each service: type, duration, price per client, capacity; "Add another service" | None |
| When are you available? | Days of the week and time slots | None |
| Review and create site | A summary of services, schedule and contact details | "Create Business Site" generates the site (below) |
| The site | The generated page with booking requests, visitor questions and reviews | Questions and reviews (below) |

Values from the form controls go straight into the Farm record; no value passes through a model.

## Narration panel

The narration panel fills a timeline from each trace: which screen produced which record field, the
prompt and JSON schema a model received, the model's raw output, the checks the copy passed or
failed, the cache result and the time each step took. It states that the Space runs the models in
full precision, while the phone runs the agent and the coder as 4-bit GGUF files.

## Live inference

| Moment | Calls | Pipeline code |
| --- | --- | --- |
| Create Business Site | `json` with the coder writes the headline, introduction and theme; `translate` renders the copy in the chosen language | `app/src/agent/websiteCreator.ts` (prompt, schema, checks, fallback copy, HTML template) |
| A visitor asks a question | `agent` answers from the approved profile only | Site logic in the bundle |
| A visitor leaves a review | `agent` returns a sentiment label for the review | Site logic in the bundle |

Booking requests turn the availability slots into held requests without a model.

## Bundle

The bundle imports the app's pure modules directly: `app/src/agent/websiteCreator.ts`,
`app/src/agent/farmRecord.ts` and `app/src/agent/swahiliTime.ts`. `app/src/agent/publication.ts`
reads the app's setup store and phone database, so the bundle needs its pure steps split into a
module without those imports; that file belongs to the coordinator owner, and the split is asked for
on #32. Every model use goes through one `Models` interface, so tests run the bundle against a
scripted implementation.

## Models

`space/models.json` lists every model once: role, repository, pinned revision, files, generation
settings and the GPU time limit for its call. The model server's loader, the README's preload list
(generated by `space/scripts/gen-readme.ts`, never edited by hand) and the narration labels all
read it.

| Role | Repository | Revision | Licence | Weights |
| --- | --- | --- | --- | --- |
| Website copy | `Qwen/Qwen2.5-Coder-1.5B-Instruct` | `2e1fd397ee46` | Apache 2.0 | 3.1 GB |
| Translation | `facebook/nllb-200-distilled-600M` | `f8d333a098d1` | CC BY-NC 4.0 | 2.5 GB |
| Agent | `google/gemma-4-E2B-it` | `3e22461f65e8` | Apache 2.0 | 10.2 GB |

Revisions are the first 12 characters of the commit SHA at planning time; `models.json` holds the
full SHA. No repository is gated, so the Space needs no Hugging Face token. Speech to text and text
to speech stay out of the Space, because the onboarding flow is a form.

## Model calls

| Call | Input | Output | Notes |
| --- | --- | --- | --- |
| `json` | prompt, JSON schema, token limit | JSON text | Output constrained to the schema, as llama.cpp's `json_schema` does on the phone |
| `translate` | text, source, target | text | Beam 4, no sampling, one sentence per call |
| `agent` | messages, tools | one tool call | Output constrained to exactly one of the given tools, as llama.cpp's `tool_choice: required` does on the phone |

The bundle calls the model server through Gradio's JavaScript client, `@gradio/client` (Apache 2.0;
decided by the user on 4 October 2026), with results cached on both sides (Caching).

The contract lives once, as zod schemas in `space/web/src/contract.ts`; a build step exports them to
`space/contract.schema.json`, which the model server validates every request against. Prompts and
schemas travel in each call; the model server holds none. Each response carries the model's
repository and revision, the milliseconds spent and whether it came from the cache.

## Caching

| Layer | What | How |
| --- | --- | --- |
| Model weights | Every file in `models.json` | `preload_from_hub` in the README downloads each pinned revision while the Space builds, into the default Hugging Face cache; at run time the loader opens files with `local_files_only=True` and `HF_HUB_OFFLINE=1`, so a missing file fails the start instead of downloading |
| GPU placement | Loaded models | Placed on the GPU when the module loads, as ZeroGPU requires |
| Connection | The bundle's link to the model server | The bundle opens one `@gradio/client` connection when the page loads and reuses it for every call |
| Model call results, in the browser | Every call the visitor's browser has made | Before calling the model server, the bundle looks up the same SHA-256 key in memory, then in IndexedDB; a hit returns at once and never reaches the server or the visitor's GPU quota. IndexedDB entries outlive a page reload, and a release that changes a model revision changes every key |
| Model call results, on the server | Every call | All three calls are deterministic (greedy or beam search, fixed settings), so each result is cached under a SHA-256 key of the call, model revision, settings and input; an in-memory LRU sits over files in `/tmp`, which last until the Space restarts |
| Interface text | Every string on every screen, in every offered language | `space/scripts/translate-ui.py` translates the English strings once with the pinned NLLB revision and writes one file per language; a changed string changes its content hash and is translated again |
| Bundle | JavaScript, CSS and images | File names carry content hashes, so browsers keep them until a release changes them |

A replayed demonstration spends GPU time only on inputs neither cache has seen. The first spike
confirms that calls made through `@gradio/client` from the bundle count against the visitor's
ZeroGPU quota.

## Build and deploy

The Gradio Space does not run bun, so `space/scripts/release.ts` builds the bundle, exports the
contract schema, regenerates the README preload list from `models.json`, translates changed
interface text, checks that every file is consistent, and uploads `space/` to the Space with
`huggingface_hub`. The upload token stays outside the repository.

## Checks

- The bundle's site generation, questions and reviews run in `bun test` against a scripted `Models`
  implementation.
- Each model call has a test against the contract schema.
- `space/scripts/check-config.ts` fails when a revision is missing, a README preload line differs
  from `models.json`, a language file misses a string, or the bundle uses a model role the server
  does not serve.
- The page passes the layout audit at 1280 and 1920 px wide.

## Decisions

1. Constrained decoding for `json` and `agent`, a new library: `outlines` (Apache 2.0) or
   `lm-format-enforcer` (MIT).
2. The interface languages: the hi-fi design lists English, Spanish, French, German, Vietnamese and
   Simplified Chinese; Wren's demonstration needs Kiswahili.
3. The Space's owner account and name (#47).
